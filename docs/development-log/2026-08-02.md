# NYC Taxi development record — 2026-08-02

## Outcome

The NYC forecasting path now separates deterministic validation from human
authority. A passing model gate creates a candidate; it no longer authorizes
production model replacement or forecast publication by itself. Evaluation
readiness also advanced from draft seeds to a human-reviewed first baseline.

## Development completed

- Added approval records bound to an exact action and artifact SHA-256, with a
  named reviewer and timezone-aware approval timestamp.
- Added atomic promotion of the exact approved candidate while preserving the
  existing production model after missing, invalid, or mismatched approval.
- Changed rolling model validation to produce `candidate.joblib` and report
  `awaiting_human_approval` instead of automatically replacing
  `production.joblib`.
- Required a separate approval bound to the production model before forecast
  publication can write a new product.
- Changed scheduled operations to stop after model validation. Model promotion,
  forecast publication, and monitoring remain separate human-controlled steps.
- Added regression coverage proving that negative predictions block publication
  without replacing the existing forecast or lineage.
- Reviewed the complete zone-hour grid and JFK/LaGuardia specialist-routing
  seeds, approved a golden grid example, and promoted the negative-prediction
  scenario to a reviewed failure case.
- Recorded the first human-approved evaluation baseline and aligned the
  capability declaration to `baseline_ready`.
- Declared Python 3.11 locally to match CI and added the AgentGov repository
  layout contract.
- Added README visibility for the existing AgentGov check and its authority
  limits.

## Governance impact

AgentGov validates that NYC's capability, control, evaluation, caller, source,
and evidence declarations remain internally consistent. The runtime approval
gate is NYC code; AgentGov makes that boundary review-visible but does not act
as the human approver.

NYC remains on the published AgentGov 0.2.1 workflow. The future 0.3 benefit
monitor, persona-aware surfaces, and bounded upgrade proposal workflow are not
yet adopted here and must not be presented as current NYC behavior.

## Human decisions retained

- A deterministic PASS does not authorize model promotion or publication.
- Approval is specific to one action and one artifact digest; it is not a
  reusable repository-wide permission.
- AgentGov does not merge, release, deploy, schedule production work, or infer
  that a workflow-only change improved forecast quality.
