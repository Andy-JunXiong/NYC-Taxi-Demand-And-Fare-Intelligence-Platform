## Recursive evaluation identity-binding design

This design-only slice reviewed existing model-digest enforcement and prepared
[`../recursive-evaluation-identity-binding-design-2026-08-24.md`](../recursive-evaluation-identity-binding-design-2026-08-24.md).
It proposes binding future staggered runs to the exact candidate bytes, a
canonical executable JSON plan, and one named reviewed block before model
deserialization or outcome access.

The design keeps Markdown as human-readable rationale rather than using its raw
bytes as the deterministic gate, because checkout line-ending normalization can
change a Markdown byte digest without changing reviewed semantics. The proposed
JSON plan instead rejects duplicate and unknown keys, validates a closed schema,
and hashes canonical parsed content. Its candidate identity remains the exact
v2 model SHA-256; rebuilt bytes cannot inherit it.

The design also requires model verification before `joblib.load`, plan and
model re-verification before staging-report replacement, an explicit bound
identity record in the output, and rejection of any unbound non-zero origin
step. It defines no threshold and changes no implementation.

## TLC source-availability gate

official TLC object before a range download begins. HTTP `403` and `404` are
classified as `source_not_available` and emitted in one structured JSON report
with `writes_performed: false`. If any month is unavailable, no requested month
is downloaded, preventing a partially advanced range.

code and stops before Silver construction, quality-gate output, Gold
replacement, or lineage writes. Existing local files still skip network checks
unless `--force` or the explicit `--check-availability` mode is used. Available
sources retain the existing atomic `.part` download and manifest behavior.
